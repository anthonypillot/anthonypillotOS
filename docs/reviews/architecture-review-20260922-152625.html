SolutionConcentrate discovery decisions in a frontend module so callers can present tools without reconstructing landing/play meaning, while retaining editorial differences locally.

Depth / deletion testDepth exists only if deleting the module would spread discovery rules back across callers; merely relocating an array while callers retain every decision is deduplication.

Tests through the interfaceKeep current menu and catalog browser assertions; add footer and nested-route checks with independently authored expected destinations so shared incorrect data cannot validate itself.

Adapter disciplineNo external adapter is needed for in-process discovery. The three real consumers justify leverage, but are not evidence of interchangeable adapters or a new pluggable seam.

Current evidenceMenu and catalog already have strong keyboard, routing and responsive tests; this is change-locality friction, not a demonstrated broken destination.

  • locality: discovery decisions live together
  • leverage: one change, three presentations

The deletion-test filter

  • IT Facts round extraction: current rules already have reasonable locality; a new module pays off only with a deliberate deterministic-test strategy, reopening design D1/D7.
  • Universal animation / hero framework: different lifetimes and visual treatments do not establish interchangeable adapters; local lifetime fixes offer more leverage today.
  • Generic cleaner-provider framework: one implemented deletion category is not evidence of future variation.

Review rule: the interface is the test surface. One adapter means a hypothetical seam; two adapters mean a real one. Add depth by removing knowledge from callers, not by adding files.

Top recommendation

It combines concrete completion gaps, repeated recent edits, two consumers of the same result, and an existing server test harness—strong locality and leverage with fewer distributed-state decisions than the Task Hold’em round refactor.
